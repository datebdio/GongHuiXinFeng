# ACCEPTANCE.md

验收采用“业务闭环 + 自动化测试 + 客户可见 UI”三层标准。

## A-01 核心闭环
必须完整跑通：
抢单 → 学习 → 答题 → 打卡 → 金币/红包结果 → 金币累计 → 商城兑换 → 兑换码 → 商家核销。

## A-02 登录与认证
- 首次微信登录可建立账户。
- 可选择外卖骑手/快递员并上传三选一材料。
- 后台可通过/驳回并保留审核历史。
- 驳回可重新提交。
- 权限矩阵符合 D-AUTH-001。

## A-03 抢单
- 时段、名额、每日次数可配置。
- 未开始/进行中/抢完/结束状态正确。
- 200 并发场景不得超卖。
- 同一请求重复提交不得重复占名额。
- 抢单成功生成 3 分钟 deadline。
- 超时可自动过期并释放名额。
- 目标：抢单接口 P95 ≤500ms（在约定测试环境和 200 并发基线下记录结果）。

## A-04 学习与答题
- 视频/语音可正常播放。
- 1~3 道单选题可随机组题。
- 中途退出可恢复，时间规则符合 BR-GRAB-008。
- 结果正确记录答题数、正确数、时间。
- 完成后只允许结算一次奖励。

## A-05 金币
- 所有金币规则后台可配置。
- 获得、消费、过期、人工调整均有流水。
- 任何重复回调/请求不得重复发币或扣币。
- 余额 = 有效流水计算结果。
- 等级按 lifetime_earned 计算，消费后不降级。

## A-06 红包
- Mock 模式可完整演示命中/未命中、记录、状态流转。
- 若接真实资金通道：同一奖励不得重复发放；外部单号可追踪；失败可重试/人工处理；资金记录可审计。

## A-07 商城
- 支持纯金币商品。
- 数据模型支持金币+现金商品。
- 并发兑换不得超卖。
- 创建订单与扣币不得出现半完成状态。
- 生成唯一核销码/二维码。
- 已核销订单不可再次核销。
- 过期策略符合后台配置。

## A-08 后台
工会管理员无需开发人员协助即可：
- 审核认证；
- 上传/编辑/审核内容；
- 管理题库；
- 配置抢单时段与名额；
- 配置金币/红包规则；
- 上下架商品、查看订单；
- 发布公告；
- 查看核心数据。

## A-09 数据看板
至少展示：
注册用户、认证用户、DAU/MAU、抢单参与率、学习完成率、答题正确率、金币发放/消耗、红包发放/使用、商城兑换率、时段活跃、内容完成、等级分布。

统计延迟目标 ≤10 分钟。

## A-10 性能与兼容
- 常规页面目标加载 ≤2 秒。
- 抢单接口目标 ≤500ms。
- 支持客户预估单场 ≤200 并发。
- 兼容微信小程序最新基础库及前两个版本。
- 主流 iOS/Android 分辨率基础适配通过。

## A-11 安全
- 敏感数据不明文暴露。
- 认证材料受控访问。
- 关键接口具备鉴权、限频、幂等、防重放基础机制。
- 管理员关键操作有审计日志。
- 基础依赖漏洞扫描无高危未处理项。
- 不在仓库提交真实密钥、商户证书、AppSecret。

## A-12 客户验收
客户原方案提出：
- 至少 10 名骑手参与内测；
- 满意度 ≥80%；
- 工会管理员可独立完成内容上传、活动配置、数据查看。

开发阶段将前两项视为上线前业务验收，不作为本地代码自动测试条件。

## Definition of Done（单任务）
一个 TASK 只有同时满足以下条件才算完成：
1. 实现满足对应 BR/P/DM 编号；
2. 新增/更新自动化测试；
3. lint/typecheck/test 通过；
4. 不引入未确认的 OPEN 决策；
5. 必要文档同步更新；
6. PR 描述列明验证方式与已知限制。

# DECISIONS.md

状态值：`OPEN` / `ACCEPTED` / `REJECTED`。  
Codex 不得自行解决 `OPEN` 决策。

## P0 — 开发前必须确认

### D-LEVEL-001 等级命名
- 状态：OPEN
- 冲突：原方案前段为“新蜂骑手/铜牌骑手/银牌骑手/金牌骑手/抢单王”，后段为“新锋骑士/铜牌新锋骑士/银牌新锋骑士/金牌新锋骑士/王牌新锋骑士”。
- 推荐：采用后段“新锋骑士”体系，品牌一致性更好。

### D-AUTH-001 身份审核前可用权限
- 状态：OPEN
- 原方案：提交认证后可直接参与；审核通过后解锁完整功能。
- 推荐：提交后可浏览、学习、抢单；审核通过后才允许领取现金红包、商城兑换、提现/资金相关功能。

### D-REWARD-001 抢单完成奖励关系
- 状态：OPEN
- 冲突：部分表述为“随机红包或金币”，核心流程又表现为“金币+红包”。
- 推荐：每次完成必得金币；红包按后台概率随机命中。这样奖励可控且更符合“惊喜感”。

### D-REWARD-002 速度/正确率与奖励算法
- 状态：OPEN
- 原方案只说“根据速度+正确率派发”，没有公式。
- 推荐：MVP 不用速度影响金额；答题达到通过线即可领取配置金币，红包由活动概率池随机。速度仅用于排行榜，避免复杂且难解释的资金规则。

### D-REDPACK-001 红包真实资金方案
- 状态：OPEN
- 选项：A. 微信商户真实发放/转账能力；B. 仅内部红包余额，线下/人工结算；C. MVP 暂不开放真实现金。
- 推荐：开发期使用 Mock Provider；上线前根据工会主体商户资质决定 A/B。

### D-CONTENT-001 “自动抓取公众号文章”实现
- 状态：OPEN
- 风险：原方案未提供公众号接口、授权方式和可用技术路径。
- 推荐：MVP 后台录入/粘贴文章链接 + 标题/封面/金币；保留 ContentSourceProvider，确认官方可用接口后再自动化。

### D-TECH-001 技术栈
- 状态：OPEN
- 推荐：微信原生小程序 + TypeScript + TDesign；Vue 3 + Vben Admin；NestJS + Prisma + MySQL + Redis。

### D-SHOP-001 金币+现金商品是否首期上线
- 状态：OPEN
- 推荐：功能结构保留，首期先完成纯金币闭环；真实微信支付在商户号、退款、对账方案确认后开启。

## P1 — UI 原型后、后端实现前确认

### D-GRAB-001 视频加载失败是否暂停 3 分钟倒计时
- 状态：OPEN
- 推荐：服务端 deadline 不暂停，但若平台确认是服务异常则管理员可补偿；实现简单且防滥用。

### D-LEVEL-002 联盟加入机制
- 状态：OPEN
- 推荐：等级达到金牌后出现“申请资格”，最终由管理员审核/邀请；王牌自动获得更高优先级但不自动加入。

### D-TAB-001 “领金币 Tab”正式名称
- 状态：OPEN
- 冲突：正文叫“领金币 Tab”，页面清单叫“学习中心 Tab”。
- 推荐：底部 Tab 用“学习”，页面标题“学习中心”，避免功能名称过于功利；金币奖励在卡片中突出。

### D-SHARE-001 分享奖励如何判定
- 状态：OPEN
- 风险：仅点击分享按钮就发币容易刷；微信也无法可靠证明对方实际阅读。
- 推荐：MVP 记录“有效分享事件”并限频，每日最多 2 次/10 金币；后续再按落地访问做增强。

### D-MERCHANT-001 商家端形态
- 状态：OPEN
- 选项：A. 管理后台商家子账号；B. 独立商家小程序/页面。
- 推荐：MVP 用后台商家子账号完成核销与订单查看，不额外开发第二个小程序。

### D-VERIFY-001 实物/服务核销是否必须到店
- 状态：OPEN
- 推荐：商品配置 fulfillment_type（STORE_VERIFY / ONLINE / DELIVERY），首期以 STORE_VERIFY 为主。

### D-PRIVACY-001 排行榜昵称展示规则
- 状态：OPEN
- 原方案要求保护隐私。
- 推荐：昵称首字 + ** + 尾字（不足长度按规则脱敏），同时展示等级，不展示手机号/真实姓名。

## 已从客户方案直接确定，无需再讨论
- 学习内容原则上 ≤1 分钟。
- 抢单成功后需在 3 分钟内完成学习与答题，否则名额释放。
- 每场名额、每日次数、金币奖励、红包范围、金币有效期、兑换码有效期均后台可配置。
- 金币不可直接提现，红包与金币分账。
- 商城支持纯金币及金币+现金的业务模型。
- 管理后台需要用户、认证、内容、题库、抢单、金币红包、商城订单、公告、数据看板。
- 单场预计瞬时并发 ≤200，抢单接口目标 ≤500ms。

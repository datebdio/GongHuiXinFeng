状态：T101~T108 已完成；T109 沙盒自动验收已完成，微信开发者工具实际验收待执行。

## 1. 设计方向

关键词：年轻骑手、城市服务、工会温度、轻量、可信、现代。

- 工会红作为主要操作强调色，不使用满屏政务红；
- 暖橙/金币色用于奖励与成长；
- 大面积浅灰白背景 + 圆角卡片；
- 首页“立即抢单”是第一视觉焦点；
- 学习、金币、红包有轻游戏化反馈，但不使用赌场/抽奖视觉；
- 所有外部能力均为 Mock，不读取真实微信用户数据、不产生资金交易。

主题 Token：`apps/miniprogram/styles/tokens.wxss`。

## 3. 演示流程

### 场景 A：首次用户

1. 登录页勾选协议；
2. 点击“微信一键登录”（Mock）；
3. 选择外卖骑手/快递员；
4. 选择三类认证材料之一；
5. 点击添加示例材料并提交；
6. 状态进入“审核中”，回到首页。

符合 D-AUTH-001：审核中仍可学习、抢单、浏览商城，但不可实际兑换/现金权益。

### 场景 B：抢单核心闭环

首页底部“原型演示”可切换五种状态：

- `WAITING` 未开始；
- `OPEN` 可抢；
- `SOLD_OUT` 已抢完；
- `FINISHED` 已结束；
- `CLAIMED` 已抢到。

推荐演示：切换到 `OPEN` → 立即抢单 → 进入 3 分钟任务 → 模拟完成 1 分钟学习 → 3 题答题 → 结果页 → 打卡并领取 → 返回首页。

奖励规则遵循已冻结决策：通过任务后固定配置金币，红包按 Mock 概率命中；答题速度不影响奖励金额。

### 场景 C：商城权限

1. 审核中进入商城，可浏览商品与商品详情；
2. 点击兑换会明确提示“认证审核通过后可兑换”；
3. 在“我的”底部原型控制切换为“已认证”；
4. 再进入纯金币商品，可查看 Mock 兑换确认；
5. “金币 + 现金”商品仍提示首期暂未开放，避免提前固化真实微信支付。
